## Proposed content boundary

`website_pages` is one page-scoped managed document/version for Shop, PDP, Sold Out, About, Contact, FAQ and the four existing policy routes. `website_page_sections` holds only fixed, allowlisted presentation sections; `website_faq_categories` and `website_faq_items` normalize the FAQ; `website_policy_sections` holds ordered policy sections with plain-text paragraph arrays. No product, order, inventory, customer, review or blog data is copied. A missing page row means the current source-controlled content remains authoritative. A successful first save creates that page row and makes that page managed-authoritative; an empty database can never blank an existing page. Home/Footer keep their existing independent save/version model.

The editor loads a page-specific document and edits it locally. The same real storefront component renders both public and same-origin iframe preview, with unsaved data injected by postMessage. Preview does not save. Each page uses its own `updated_at` token; a stale save raises `PT409` and is never retried automatically. Policy routes each have their own version. The FAQ has one version covering its categories and items.

The proposed media path is `pages/{page_key}/{sha256}.{jpg|png|webp}` in the existing private `percent-website-media` bucket. Before page image controls are enabled, the Edge Function must allowlist page keys and paths, retain magic-byte and Admin role checks, use admin-only preview signing, permit public signing only for image paths returned by live managed page RPCs, and block cleanup of any referenced path. No new bucket or browser service key. The SQL in the handoff validates the path metadata but does not change the Edge Function.

Public RPC reads return enabled sections/FAQ entries and existing managed page presentation only. Admin read/save RPCs verify `auth.uid()` and `private.is_admin()`. All tables have RLS enabled and no direct anon/authenticated grants. Plain text is rendered as text, not HTML. CTA paths are restricted to local paths. The database design needs five new tables, no changes to existing tables, one public read RPC, one Admin read RPC, and one Admin save RPC. Deleting these tables/RPCs would remove only Phase 7B managed content; existing Home/Footer and code-owned fallback would remain, but any saved Phase 7B edits would be lost. Back up rows and referenced media before rollback.
